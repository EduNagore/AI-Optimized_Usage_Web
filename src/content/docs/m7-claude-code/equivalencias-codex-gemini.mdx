<KeyTakeaways>

- Las tres herramientas comparten la idea (agente en terminal con ficheros de instrucciones, skills, subagentes y hooks) pero no los nombres ni los formatos.
- Codex usa `AGENTS.md` y tiene `/plan`, `/review`, `/goal`, `/model` o `/compact`; en su CLI el esfuerzo de razonamiento se elige desde `/model`.
- Gemini CLI ya no atiende a las cuentas de consumo (AI Pro, AI Ultra y Code Assist individual): las sustituye Antigravity CLI (`agy`).
- Donde la documentación oficial que hemos podido leer no lo confirma, esta tabla dice «no confirmado» en lugar de suponerlo.
- `/import` de Claude Code trae la configuración de Codex, Gemini CLI o Cursor; Codex tiene un `/import` equivalente para traer la de Claude Code.

</KeyTakeaways>

## La idea

Cambiar de herramienta de agente de código no es empezar de cero: el modelo mental es el mismo. Lo que cambia es cómo se llama cada pieza y dónde vive. Esta página es una tabla de traducción para quien trabaja con más de una herramienta o está migrando.

<Callout tipo="varia">

Estas herramientas cambian de nombre, de comandos y de planes con frecuencia, y cada proveedor documenta de forma distinta. Todo lo que sigue sobre Codex, Gemini CLI y Antigravity CLI «varía según el proveedor» y puede haber cambiado desde la última revisión. Donde no pudimos confirmar un dato en la documentación oficial, aparece como **no confirmado**: no lo des por hecho sin comprobarlo en tu instalación.

</Callout>

## Codex

Codex está disponible en varias superficies: la app de escritorio de ChatGPT, la app móvil, ChatGPT en la web, la CLI, la extensión de IDE y Codex Cloud. Sus instrucciones permanentes viven en `AGENTS.md`: se cargan desde `~/.codex` y desde la raíz del proyecto hasta el directorio actual, y los ficheros más cercanos al directorio de trabajo prevalecen.

Tres diferencias que conviene recordar al migrar:

- **El esfuerzo se elige desde `/model`.** Lo que en Claude Code es `/effort`, en la CLI de Codex forma parte de `/model`, y los niveles dependen del modelo. Ver [esfuerzo y razonamiento](/AI-Optimized_Usage_Web/m4-modelo-y-esfuerzo/esfuerzo-y-razonamiento/).
- **Los permisos son perfiles, no modos.** Un perfil define qué puede escribir y si hay red; los perfiles no se combinan con las opciones antiguas de sandbox: usa uno u otro. Si el revisor automático deniega una acción, `/approve` permite reintentarla una vez.
- **`codex exec` parte de un sandbox de solo lectura.** Para permitir ediciones hay que pedirlo explícitamente (`--sandbox workspace-write`), mientras que en `claude -p` el equivalente lo decides con `--permission-mode` y `--allowedTools`.

## Gemini CLI y Antigravity CLI

<Callout tipo="novedad" fecha="2026-10-19">

Desde el 18 de junio de 2026, Gemini CLI y las extensiones de IDE de Gemini Code Assist dejan de atender las solicitudes de las cuentas Google AI Pro y Ultra y del nivel individual de Code Assist, según el anuncio de Google. Las sustituye **Antigravity CLI**, cuyo comando es `agy`. Gemini CLI sigue disponible con licencias Code Assist Standard o Enterprise y con claves de API de pago. La página de modo headless de la propia documentación de Gemini CLI ya recoge la sustitución. **Qué hacer:** si tu organización tiene licencias Standard o Enterprise, o usas una clave de API de pago, sigue con Gemini CLI. Si no (cuenta personal AI Pro o Ultra), pasa a `agy`.

</Callout>

Antigravity CLI conserva Agent Skills, hooks, subagentes y extensiones (ahora plugins), pero **no hay paridad uno a uno** en el lanzamiento. De Gemini CLI hemos confirmado que su fichero de contexto es `GEMINI.md`, que el modo no interactivo se activa con `-p` y que la documentación tiene páginas de modo plan, skills, subagentes, hooks y extensiones; no hemos podido contrastar la lista completa de sus comandos `/`. Por eso las columnas de Gemini y Antigravity tienen tantos «no confirmado»: preferimos decirlo antes que inventar equivalencias.

## En la práctica

Empezar un proyecto nuevo en cada herramienta:

## Ejemplo de oficina: un equipo con dos herramientas

Un equipo de análisis usa Claude Code, pero una persona nueva viene de Codex. Reglas del equipo para convivir:

1. Un único fichero de instrucciones por proyecto. Claude Code lee `AGENTS.md` si no hay `CLAUDE.md` en el directorio, así que mantener solo `AGENTS.md` evita duplicados.
2. Las skills y los subagentes se documentan en el repositorio con su nombre y para qué sirven, para poder portarlos a mano si se cambia de herramienta.
3. La persona nueva ejecuta `/import codex --dry-run` y revisa antes de aplicar.

Por qué: mantener un solo fichero de instrucciones evita que dos copias se desincronicen y el equipo pague contexto por reglas contradictorias.

## Errores frecuentes

- **Asumir que un comando equivale en otra herramienta.** `/effort` no existe en la CLI de Codex: allí el esfuerzo se elige desde `/model`.
- **Seguir usando Gemini CLI con una cuenta de consumo.** Ya no atiende esas cuentas; pasa a `agy`.
- **Copiar `CLAUDE.md` a otra herramienta sin revisarlo.** Puede mencionar comandos, skills o hooks que allí no existen.
- **Fiarse de tutoriales de terceros sobre listas de comandos.** Cambian cada semana. Comprueba con `/help` en tu instalación.
